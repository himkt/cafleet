============================================================
"Currently `cafleet monitor` sends a nudge not only to the monitoring member but ALSO to the Director. Monitoring should be done ONLY for the monitoring member, which lets the monitoring member check the Director's progress and nudge the Director on demand. THE CENTRAL OPEN QUESTION you MUST raise as a clarifying question
============================================================
If the Director is removed from the heartbeat, then any fleet that runs the monitor WITHOUT a monitoring member loses the Director's wake backstop. Today the Director is still woken by the broker's inline-preview keystroke on every inbound `message send`; the heartbeat poll is only a backstop. BUT several skills currently start the monitor and rely on the Director being polled:
- skills/cafleet-design-doc-create, skills/cafleet-design-doc-execute, research skills: their older steps have the DIRECTOR run `cafleet monitor start` directly (no monitoring member), whereas the newer skills/cafleet-agent-team-monitoring and skills/cafleet-agent-team-supervision say the MONITORING MEMBER runs `cafleet monitor start` and the Director never does.
There is already drift between these skills. The design doc should resolve it: after this change, is a monitoring member REQUIRED for the heartbeat to do anything useful? What happens to a fleet with the monitor running but no monitoring member (heartbeat targets nobody)? Should `monitor start` warn / no-op? Surface concrete options for the user to choose.
