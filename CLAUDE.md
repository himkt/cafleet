# Repository policy

CAFleet is a Rust CLI with embedded skills/presets and an independently built documentation site.

## Ownership and commands

Assigned members continue their existing team, load the installed core/backend/member references and follow scoped ownership. The Director owns Git, user decisions, lifecycle and publication. Preserve active teams' installed binary/assets; validate checkout builds with isolated database/configuration and disposable owned panes.

Run project operations from the repository root with mise full-path tasks. Use `mise tasks` and package task definitions as the task registry. Run the validation and build tasks defined by each affected package, including the documentation site when its operator guidance changes.

Run one command per shell invocation, use literal IDs and file editing tools for output, and route observed necessary command denials to the Director. Host rules govern permissions and Git handling. Keep design/research artifacts outside commits; use English, single-line conventional commit messages and ordinary staging.

## Storage and implementation

Migrations under `cafleet/migrations/` own storage shape. Add contiguous current-family migrations, preserve existing migration files/checksums and application data, and refuse incompatible/ahead databases before mutation. Preserve short transactions, pane-input ownership, under-lock revalidation, absolute deadlines, completion grace and durable messages.

Express intent through names and structure. Validate required state at its source and surface failures; defaults represent documented valid absence. Add comments only for constraints or reasons the code cannot express. Keep necessary unit coverage inline in owning production files and use proportionate checks.

## Writing and removal

Write files in English and conversation responses in the user's requested language. The site owns operator behavior, skills own agent procedure, CLI help owns options and source owns rendering. Update affected documentation with behavior changes.

State desired behavior directly. Describe growing groups through their selecting property or source of truth. Complete removal across maintained source, docs, examples and registrations in the same change; preserve historical design/research records.
