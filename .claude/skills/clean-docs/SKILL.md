# Clean documentation

Read the assigned scope, repository policy and relevant implementation. Keep operator behavior in the site, agent procedure in skills, options in CLI help and storage shape in migrations.

1. Find inaccurate, duplicated, obsolete or ambiguous content within the requested scope.
2. Rewrite each owner as a concise statement of intended behavior. Preserve useful examples, constraints and actionable failure/recovery instructions.
3. Describe growing groups through their selecting property or link to their source of truth.
4. Complete feature/path removal across maintained references and registrations; preserve historical artifacts.
5. Check local links/anchors, navigation, embedded runtime mirrors and applicable content budgets. Run relevant existing build/check tasks.
6. Report findings or changes with concrete paths, evidence and remaining limitations.

For substantial multi-file work, use scoped CAFleet members and independent review through the [CAFleet skill](../../../skills/cafleet/SKILL.md). Continue an existing assigned team. The Director supplies absolute paths, receives ready, reads full reports and owns Git/user decisions. Routine edits use proportionate validation.

Prefer names, structure and direct prose over reactive prohibitions. Include a hard constraint when it clarifies the intended behavior, paired with the positive instruction it protects.
