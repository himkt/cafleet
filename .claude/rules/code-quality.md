# Code Quality

## No meaningless fallbacks

Do NOT reach for a defaulting accessor when the value is guaranteed to exist. Use direct access and let the code fail loudly if the assumption is wrong.

**Banned patterns:**

| Language | Banned | Use instead |
|----------|--------|-------------|
| Rust | `map.get("key").cloned().unwrap_or_default()`, `opt.unwrap_or(0)` when the invariant guarantees presence | `map["key"]`, `opt.expect("<why the invariant holds>")` |
| Rust | `row.get("col").unwrap_or_else(\|_\| String::new())` | `row.get("col")?` / `.expect(...)` — surface the error |
| TypeScript | `value \|\| "Unknown"`, `value ?? "?"` | `value` (trust the type) |

**Exceptions** (where a default IS appropriate):
- A default that is the documented correct behavior for an expected absent value (e.g. an optional config field with a sensible default)
- Data from external/untrusted sources where the schema is not guaranteed

When in doubt, prefer a loud panic or a typed error over a silent wrong value.

## No unnecessary comments

Only add comments where the logic is genuinely non-obvious. Do NOT add:
- Comments that restate the code (`// Create the session`, `// Return the result`)
- Doc comments that restate the test name or type name
- Multi-paragraph explanations of design decisions (put those in design docs)
- Comments explaining what a function's parameters do (use the type signature)

## Test placement

Every Rust test is an in-file unit test. It lives in one `#[cfg(test)] mod tests` block at the end of the implementation file whose behavior it exercises, and `mise //:test` runs it.

- Place each test in the file that defines the entry point it asserts on. When a test drives several files, the file that owns the asserted behavior owns the test. Group related tests in nested modules inside `mod tests`.
- Put a helper shared by tests in several files into the implementation file that owns the type it builds, as `#[cfg(test)] pub(crate) mod test_support`. A test-only constructor or method on a production type is a `#[cfg(test)] impl` block beside that type. A helper used only by one file's tests stays inside that file's `mod tests`. Crate-wide test macros are defined at the top of `main.rs`, before the first `mod` declaration. Reuse an existing helper or production function (clocks, digests, frame codecs, fixtures) before writing another.
- Write test inputs as literals or generated bytes inside the test module. Every test drives production code and asserts what that code decides or produces. A test uses the data files that production code embeds (every file under `assets/`) only as input to that code or as the expected value of its output, such as comparing installed bytes with the embedded bytes, and asserts none of their text, keys, counts, ids or layout.
- Name a re-executed child test with `test_path!` beside the child, so moving a module keeps every launcher correct.
- Test-only harness code is itself test code: it is an inline `#[cfg(test)]` module of the implementation file it instruments.

**Forbidden patterns:**
- A test-only `.rs` file or directory: `*_tests.rs`, `*_tests/`, `tests/`, a `#[path]`-mounted test file, or a `#[cfg(test)] mod name;` declaration that loads a separate file.
- A test-only fixture file or fixture directory.
- A test module that exercises another file's implementation.
- A module named `tests` that holds only shared helpers; name it `test_support`.
- A test that asserts the text, keys, counts, ids or layout of an embedded data file instead of the behavior of the code that consumes it.

## Database schema

`assets/migrations/V1__baseline.sql` is the complete schema and the only file in `assets/migrations/`; edit it in place for every schema change. Each cafleet version uses its own default database file, `cafleet_<VERSION>.db`, so every release starts from a fresh database and no data carries across versions. Baseline initialization records the creating version in `cafleet_database`. Setup and the command guard accept only a file whose application identity, ledger, recorded version and required table/column shapes match the running binary, and refuse every other populated file as incompatible without writing to it.
